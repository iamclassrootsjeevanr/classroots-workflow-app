- Tailwind v4: any class that is `@apply`'d elsewhere must be defined with `@utility`, not inside `@layer components`, or `next build` fails with "Cannot apply unknown utility class".
- Colour tokens that change per theme must go through `@theme inline` (resolves where used); plain `@theme` resolves at `:root` only, so dark mode would not apply.
- Cookies set from a server action are URL-encoded; keep cookie values free of `=`/`&` (the prefs cookie uses `.` separators) and `decodeURIComponent` defensively when parsing.
- Theme: the inline script resolves "system" on the client, so React's `data-theme` prop ("light" for system) can differ from the DOM. After a client navigation that changes the preference (e.g. sign-in), React skips unchanged props; `ThemeWatcher` re-syncs `data-theme` on every `theme` change.
- One-off tsx scripts that import `src/server/services/*` hit `server-only` and crash; run them with `npx tsx --conditions=react-server --env-file=.env <script>`.

ADMIN_EMAILS only makes *new* accounts admin; existing ones need the Admin switch. Don't re-run `npm run demo:users`: it re-creates the demo accounts and duplicate Jeevan / Demo Admin.
- Embedded Postgres must be running (`npm run db:start`) before `prisma migrate deploy`, otherwise P1001.
- `start.command` runs the DB and `next dev` together: stopping its `next dev` also stops the DB via its EXIT trap. It now refuses to start a second copy (port 3000 in use → just opens the browser), runs `prisma migrate deploy` + `prisma generate` and clears `.next` before `npm run dev`. Agents: don't leave a background `next dev` running when handing back; a double-click then reuses it, and a stale one (old Prisma client, broken `.next`) shows 500 "ENOENT .next/server/…".
- `getModule` / `requireModule` return the module merged with admin stage edits (WorkflowStage). Scripts must `await refreshStages(true)` first; tests use `requireModule(key)` or `applyStageConfig(base, [])` — the raw definition has no generated "next" moves.
- Demo sign-in for local checks: accounts from `scripts/demo-users.ts`, password `DEMO_PASSWORD` in `.env` (git-ignored).
- Never run two `next dev` servers on the same checkout: they share `.next/` and corrupt it ("Cannot find module './vendor-chunks/…'"). Check `lsof -iTCP:3000` first; if it's corrupted, stop all servers and `rm -rf .next`. `AUTH_URL` is pinned to port 3000, so sign-in only works there.
- Wide tables: `w-full` tables never overflow (browser squeezes columns), so nothing scrolls. Use the `.sheet` grid (`width:max-content; min-width:100%`) inside `<Sheet>`; style scrollbars with `::-webkit-scrollbar` because macOS overlay scrollbars are invisible until you scroll.
- Overlays: a `position: fixed` dialog inside a sticky/positioned table cell is trapped in that cell's stacking layer and paints under sticky headers. Render dialogs with `createPortal(..., document.body)`. `.sheet-wrap` uses `isolation: isolate` so table z-indexes stay below the phone top bar (z-30), drawer (z-40) and dialogs (z-50). Avoid `data-tip` tooltips inside tables or scrolling dialogs (they open sideways and get clipped); use `title`.
- Don't run `npx prettier` on files here: there is no project config, so it reformats the whole file with default quotes.

- Speed: don't pass per-row field values or option lists for hundreds of rows into client components (Items page was 7 MB / 6 s). Page lists (`pageOf`, `capPerType`) and load edit fields on demand (`loadEditFieldsAction`). `next dev` also inflates the RSC payload; judge speed on a production build.
- After a schema change (`prisma generate`) the running `next dev` keeps the old Prisma client ("Cannot read properties of undefined"); restart the dev server.
- Adding a role to a module definition is enough: Admin → Roles (or the user form) creates it. A flow capability with no role granting it fails `tests/roles.test.ts`. Changing an existing role in code does NOT update the saved role (admins may have edited it): Admin → Roles shows "Differs from the flow's default" and **Reset to default**; `npm run import:journey -- … --replace` resets the Journey roles. On 5 Nov the saved SME creator was "own data" and Coordinator lacked "edit details" until reset.
- Role checks in the browser: office emails can sign in with a password too (only Google is office-only), so give a team account a temporary local password (`hashPassword` from src/lib/password) and remove it afterwards. The full Journey role matrix is unit-tested in `tests/journey-roles.test.ts`.
- Sheet sync: the Apps Script (apps-script/Code.gs) locates a tab by name across the owner's Google Sheets, so work types need no Spreadsheet ID. It must be redeployed (new version) after edits.
- Sheet push order matters for linked trackers: `sheet.linked` tabs (Lists → Test Cases → APK Releases) are ensured before Test Execution rows (Code.gs ensureValues / ensureRows, located via the main tab so same-named tabs elsewhere are ignored).
- Sheet gotcha: Lists!D (APK Versions) is a FILTER formula over APK Releases; typing into it collapses the spill (#REF!). Code.gs ensureValues skips formula columns. Version Summary is a fixed table (row per release + Total); ensureSummary copies the last row and widens the Total ranges.
- `next start` warns with `output: standalone`; production check = `npm run build` then `npm start` (stop dev first, `rm -rf .next` before going back to dev). Prisma interactive transactions time out after 5 s: long ones (creating a version) pass `{ timeout }`.
- Teams (Journey): edit them in the app (Journey → Teams); `npm run journey:teams -- --apply` only seeds Team Arjun / Team Devjyoti and fills empty reviewers (safe to re-run, never replaces a reviewer). "Owner" in the UI = the creator's team coordinator, derived in `loadItems` (`data.teamOwner`); `WorkItem.ownerId` is still the SME reviewer. Empty `WorkTypeMember.groupKeys` = steers every chapter, so never remove a coordinator's last chapter.
- Scripts can't import `src/server/access.ts` (it pulls in `next/navigation`, which crashes under tsx even with `--conditions=react-server`); build the access with `buildAccess` from `src/lib/access-core.ts` instead. To try a write path on real data without keeping it, run `internals.*Tx` inside your own `db.$transaction` and throw at the end.
- Agents can't sign in to the local app: auto mode blocks reading `DEMO_PASSWORD` and setting temporary passwords. Ask Jeevan to sign in in the Browser pane, or verify with unit tests plus a rolled-back script.
- `.claude/launch.json` has `app` (= `start.command` without opening a browser: DB + migrate + `next dev`) besides `web` (`npm run dev`, needs the DB already up).

- APK Testing: any new query over WorkItem must choose its level. `loadItems` / `loadLiteItems` / `queryItemsPage` default to work (version items, `parentId: null`); pass `level: 'runs'` for test results or `'groups'` for group summaries. Sheet sync only touches results (`syncedItems`). Version items are app-only: `enqueue` skips them.
